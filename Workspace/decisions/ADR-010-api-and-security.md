# ADR-010：API 规范与接口安全

## 状态

Accepted

## 决策背景

当前 API 只有向量 Controller，成功为裸 DTO/数组，异常结构不统一，也没有 traceId、业务异常体系或授权过滤链。

## 决策内容

- 成功响应统一包含 `code`、`message`、`data`、`traceId`。
- 正确使用 HTTP 状态码；使用统一异常处理器和业务异常体系。
- 请求使用 traceId 追踪。
- 普通列表默认每页 20 条，最大 100 条；大数据量场景再评估游标分页。
- 重要业务/管理操作记录审计日志。
- 默认要求身份认证；服务端校验租户和知识库权限。
- 限制上传类型和大小；设置合理接口频率限制。
- Actuator 仅开放必要安全端点。

## 备选方案

- 各 Controller 自定义成功/错误结构：造成调用方解析不一致。
- 仅依靠前端校验、隐藏页面或 tenantId：无法防护直接 API 调用。

## 决策理由

**分析补充：** 统一 envelope 和异常映射降低前后端协议分歧；服务端授权及审计构成租户资源安全边界。

## 影响及约束

接口变更需同步前端 DTO、拦截器和 Workspace 契约。匿名公开接口须显式列出。Actuator 当前 health details 为 always，和最小暴露目标不一致，需在实施时受控。限流阈值、审计字段保留等细节未定。
