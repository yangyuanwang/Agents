# ADR-013：容量与性能目标

## 状态

Accepted（目标已确认，尚未验证）

## 决策背景

第一阶段需要容量规划基准。当前没有性能测试或运行负载证据。

## 决策内容

第一阶段规划目标：

| 指标 | 目标 |
|---|---:|
| 租户数量 | 100 |
| 用户数量 | 1,000 |
| Chat 并发 | 20 |
| 文档 Worker 并发 | 5 |
| 普通 API P95 | 500ms |

并发控制分为 API 层、租户层、Worker 层和模型调用层。目标通过后续压测验证并调整。

## 备选方案

当前决策没有记录被比较的数值方案；不补造历史备选目标。负载测试时可以据实形成后续调整方案。

## 决策理由

**分析补充：** 给出初期容量预算，便于部署和并发隔离评估；这些是计划目标，不是性能保证。

## 影响及约束

5 个 Worker 不等于 5 个 Embedding 请求；Chat 并发也不等同 LLM provider 并发。Worker 与 LLM/Embedding 应分别实施资源控制，避免批量任务挤占在线 Chat 能力。普通 API P95 指标需定义测试口径后验收。
