# ADR-012：数据生命周期与配额

## 状态

Accepted

## 决策背景

系统需要定义多种数据的保留、删除及租户资源治理。当前没有业务数据持久化或清理任务。

## 决策内容

- 历史数据按类型配置保留周期。
- 定期清理过期数据。
- 文档采用逻辑删除；删除后立即停止检索，后台异步物理清理且支持重试。
- 用户可主动删除自己的 Chat 会话；后台清理消息和引用。
- 审计日志采用独立保留策略。
- 第一版支持配置化租户资源配额；暂不建设计费系统。

## 备选方案

- API 请求中同步删除 MySQL、文件、Qdrant 全部数据：跨系统无共同事务且时延不确定。
- 只软删除但不安排物理清理：不满足清理要求。

## 决策理由

**分析补充：** 业务层逻辑删除与可重试物理清理可避免删除请求依赖外部存储即时可用。

## 影响及约束

逻辑删除必须在业务状态提交后立即阻止新检索结果，不能等 Qdrant point 删除完成；检索需通过权威业务状态门禁。MySQL/Qdrant/文件系统清理应幂等并可对账。Citations 不得绕过资源权限下载已删除文档。
